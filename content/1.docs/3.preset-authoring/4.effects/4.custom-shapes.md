![Custom Shapes Effect](/content/preset-guide/effect-custom-shapes.jpg){style="width: 50%;"}

Custom Shapes allow a variety of visual effects, from drawing basic shapes to moving fractals and other complex
patterns. Up to four separate Custom Shapes can be configured, each having its own code and variables.

Each shape is drawn as an n-gon with 3 to 100 sides, which are arranged in a circular pattern. There are four individual
shape effects, each of which can have separate settings and expression code. Every shape can have up to 1024 instances,
for a total maximum of 4096 individual n-gons drawn per frame.

Each drawn shape has an inner color, an outer color and a border. The fill color is blended from the center of the shape
to the outer color at the edges. The border is drawn around the shape. Additionally, each shape can be textured, which
will draw a zoomed and rotated version of the previous frame's image (the one used as input for the warp effect) inside
the shape, multiplied with the inner/outer color. The position and rotation angle can also be specified or scripted.

## Default Settings

In the preset file, Custom Shapes are prefixed with `shapecode_N_`, where `N` is the index of the shape from `0` to `3`.

The following setting keys configure the default values and initialize expression variables for each Custom Shape index:

## Expression Code Usage

For each of the four Custom Shapes, there is one initialization code block, executed once when the preset is loaded, and
a `per_frame` block, which is actually executed once per _shape instance_.

These code blocks have a different prefix than the settings above:

- `shape_N_init`
- `shape_N_per_frame`

The line number is immediately appended to these prefixes, without an additional underscore, like this:
`shape_0_per_frame1`

The following shape-specific variables are available in both `shape_N_init` and `shape_N_per_frame` code block, except

### Notes

- All variables are reset for each invocation of the `per_frame` block. To pass values from one shape instance to the
  next, use the global `regXX` variables or the shape-specific `megabuf`.
- "Writeable" means these variables can be changed to influence how this shape instance is drawn. While all variables
  can be written to, their values are discarded after the code block finishes execution.

#### Q Variable Propagation

The 32 `q` variables are propagated like this:

- Once from the preset's `per_frame_init` code to each shape's `shape_N_init` block.
- On each frame, the values are copied from the preset's `per_frame` code to each shape's `shape_N_per_frame` block on
  each instance invocation.

See this diagram for a visual representation:
![Q Var Propagation](/content/preset-guide/q-var-diagram.png){style="width: 100%;"}

#### T Variable Propagation

The 8 `t` variables are propagated like this:

- On each frame, the `t` var values are copied from the `shape_N_init` state to each shape's `shape_N_per_frame` block
  on each instance invocation.

## Drawing Caveats

### Aspect Ratio Issue

While Custom Shapes are always drawn with a 1:1 aspect ratio if the screen aspect ratio is \>1 (wider than tall),
Milkdrop has the caveat that shapes will be drawn squished in the X axis when the image aspect ratio is below 1.

This makes it very hard to align shapes properly with custom waveforms in such a scenario. Most presets performing such
an alignment, many from the early Milkdrop 1.x days, thus have expression code that positions the shape (or waveform)
accordingly. Due to this, the Milkdrop authors never fixed this bug and added a `DO NOT TOUCH`  comment on the affected
lines, as it would break a non-negligible number of presets.

### Performance Considerations

Custom Shapes are rendered sequentially, and with multiple GPU draw calls per shape instance - up to 5, if the shape is
filled and has a thick border. This will issue a total of 20.480 draw calls if all four shapes are drawn with 1024
instances and a thick border, slowing down even the most capable GPU. While this might get fixed in future versions of
projectM and Milkdrop, current and older versions suffer from this issue - mobile phones, browsers and embedded devices
even more so.

To improve performance, it is recommended to keep the number of instances low, and disabling the `thick` setting if many
instances are being used.
