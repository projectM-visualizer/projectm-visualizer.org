---
title: Shader Inputs
description: Predefined variables for use in shader code.
---

Every preset shader is compiled together with a header that declares all of its inputs. In Milkdrop, this header is
loaded from the `include.fx` file in Milkdrop's data directory, while projectM ships an equivalent header with the
library. Because of this, preset shaders can use the variables and functions listed below without declaring them.

Most inputs are identical in warp and composite shaders. The few differences are noted in the tables.

## Coordinates

| Name       | Type     | Description                                                                                                     |
|------------|----------|-----------------------------------------------------------------------------------------------------------------|
| `uv`       | `float2` | The texture coordinate of the current pixel. In the warp shader, this is the coordinate after applying the warp mesh, e.g. the result of the per-vertex code. |
| `uv_orig`  | `float2` | The original, unwarped texture coordinate of the current pixel.                                                 |
| `rad`      | `float`  | Distance of the current pixel from the screen center, interpolated from the warp mesh. `0` in the center.       |
| `ang`      | `float`  | Angle of the current pixel around the screen center, interpolated from the warp mesh.                           |
| `hue_shader` | `float3` | Composite shader only. A slowly shifting color, different in each screen corner and blended across the screen. Each channel is between `0.5` and `1`. Multiply with it to tint the image. |

## Time and Audio

| Name       | Type    | Description                                                                                                       |
|------------|---------|-------------------------------------------------------------------------------------------------------------------|
| `time`     | `float` | Time in seconds. In Milkdrop, this is the time since the _preset_ was loaded, wrapped every 10,000 seconds.     |
| `fps`      | `float` | The current frame rate.                                                                                           |
| `frame`    | `float` | The current frame number.                                                                                         |
| `progress` | `float` | Progress through the preset's display duration, from `0` to `1`.                                                 |
| `bass`, `mid`, `treb` | `float` | Immediate audio levels of the three frequency bands, relative to their long-term average. `1` is average. |
| `bass_att`, `mid_att`, `treb_att` | `float` | Smoothed ("attenuated") versions of the three levels.                                  |
| `vol`, `vol_att` | `float` | Intended as the average of the three bands. See the compatibility note below.                             |

::note
The shader `time` variable is _not_ the same value as the `time` variable in expression code. In expressions, `time`
counts seconds since Milkdrop was started, while the shader variable starts at zero whenever a preset is loaded. A
shader that needs the same timeline as the expression code should receive it through a `q` variable.
::

## Values from Expression Code

| Name             | Type    | Description                                                                                   |
|------------------|---------|-----------------------------------------------------------------------------------------------|
| `q1` to `q32`    | `float` | The `q` variables, as they are after the `per_frame` code has run for the current frame.      |
| `blur1_min` to `blur3_max` | `float` | The current minimum and maximum values of the three [blur levels](../effects/blur-textures). |

The `q` variables are the only way to pass values from expression code to the shaders. Values set in the per-vertex,
custom wave or custom shape code do not reach the shaders.

## Texture and Screen Sizes

| Name                       | Type     | Description                                                                         |
|----------------------------|----------|-------------------------------------------------------------------------------------|
| `texsize`                  | `float4` | Size of the internal render texture: width, height, 1/width and 1/height.          |
| `aspect`                   | `float4` | Aspect ratio correction: `.xy` are multipliers to make UVs aspect-correct, `.zw` their inverse. |
| `mip_x`, `mip_y`, `mip_avg` | `float` | Base-2 logarithm of the texture size, useful for choosing a mip level.             |
| `texsize_<name>`           | `float4` | Size of a user texture: width, height, 1/width and 1/height. See [External Textures](user-textures). |

Using `texsize.zw` as a step size samples exactly one neighboring texel:

```hlsl
float3 right = tex2D(sampler_main, uv + float2(texsize.z, 0)).xyz;
```

## Animated and Random Values

| Name                          | Type     | Description                                                                         |
|-------------------------------|----------|-------------------------------------------------------------------------------------|
| `roam_cos`, `roam_sin`        | `float4` | `0.5 + 0.5 * cos/sin(time * f)` for four frequencies of roughly 0.33, 1.3, 5 and 20 radians per second. |
| `slow_roam_cos`, `slow_roam_sin` | `float4` | The same for four very slow frequencies between 0.005 and 0.022 radians per second. |
| `rand_frame`                  | `float4` | Four random values between `0` and `1`, new every frame.                            |
| `rand_preset`                 | `float4` | Four random values between `0` and `1`, chosen once when the preset is loaded.      |
| `rot_s1` to `rot_s4`          | `float4x3` | Rotation matrices with a random orientation chosen at preset load. `rot_s1` does not move; the others turn very slowly. |
| `rot_d1` to `rot_d4`          | `float4x3` | Slowly turning random rotations.                                                   |
| `rot_f1` to `rot_f4`          | `float4x3` | Faster turning random rotations.                                                   |
| `rot_vf1` to `rot_vf4`        | `float4x3` | Very fast turning random rotations.                                                |
| `rot_uf1` to `rot_uf4`        | `float4x3` | Ultra fast turning random rotations.                                               |
| `rot_rand1` to `rot_rand4`    | `float4x3` | Completely random rotations, new every frame.                                      |

The roaming values and rotation matrices use the time since Milkdrop was started, so they continue smoothly when a new
preset is loaded. The rotation speeds increase steadily from `rot_s1` to `rot_uf4`: Milkdrop scales each matrix's random
speed by `0.9 * (n / 8)^3.2`, where `n` is the matrix index from 0 to 19.

Multiplying a 3D coordinate with one of these matrices rotates it, for example to animate a 3D noise lookup:

```hlsl
float3 p = mul(float4(uv, 0.5, 1), rot_d1);
ret = tex3D(sampler_noisevol_lq, p).xyz;
```

## Helper Functions

| Function        | Description                                                                                    |
|-----------------|------------------------------------------------------------------------------------------------|
| `GetMain(uv)`   | Samples the main texture: `tex2D(sampler_main, uv).xyz`.                                       |
| `GetPixel(uv)`  | Same as `GetMain(uv)`.                                                                         |
| `GetBlur1(uv)`  | Samples blur level 1 and restores its original color range. See [Built-In Textures](built-in-textures). |
| `GetBlur2(uv)`  | Same for blur level 2.                                                                         |
| `GetBlur3(uv)`  | Same for blur level 3.                                                                         |
| `lum(color)`    | Returns the luminance of a `float3` color, `dot(color, float3(0.32, 0.49, 0.29))`.             |

## Writing to Inputs

The inputs are shader constants. HLSL allows assigning a new value to them, e.g. `q5 = 0;` or `time *= 0.5;`. The
assigned value is only visible to the current pixel and is reset for the next one. To keep shaders readable and
portable, copy an input into a local variable before changing it:

```hlsl
float t = time * 0.5;
```

## Compatibility Notes

projectM provides the same inputs, but a few values differ from Milkdrop:

- **`time`**: projectM passes the time since projectM was started, not the time since the preset was loaded.
- **`vol` and `vol_att`**: Milkdrop's code calculates these with a C comma expression, `0.3333 * (bass, mid, treb)`,
  which evaluates to one third of `treb`, not the average of all three bands. projectM passes the real average.
- **`mip_y`**: Milkdrop calculates `mip_y` from the texture width instead of the height. projectM uses the height.
- **`texsize`**: Milkdrop passes the size of its internal render texture, which may differ from the window size.
  projectM passes the size of the rendering viewport.
- **`rand_frame`, `rand_preset` and the rotation matrices**: Milkdrop uses one set of values per frame or preset, shared
  by the warp and composite shaders. projectM chooses them separately for each shader, so the warp and composite shaders
  see different random values.
