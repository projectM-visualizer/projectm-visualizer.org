---
title: External Textures
description: Loading and using user-defined images in shaders.
---

Shaders can sample image files in addition to the [built-in textures](built-in-textures). An image is loaded by
declaring a sampler named after the file, without its extension:

```hlsl
sampler sampler_clouds;     // loads "clouds.jpg", "clouds.png" etc.

shader_body {
    float3 c = tex2D(sampler_clouds, uv).xyz;
    ret = GetMain(uv) * 0.9 + c * 0.1;
}
```

The [filtering and wrapping prefixes](built-in-textures#filtering-and-wrapping) also work with external textures, e.g.
`sampler_fc_clouds` loads `clouds` with bilinear filtering and clamped edges.

## Locating Image Files

Milkdrop looks for each texture in this order:

1. The `textures` directory inside Milkdrop's installation directory.
2. The directory containing the preset file.

In each directory, the file extensions `jpg`, `dds`, `png`, `tga`, `bmp` and `dib` are tried in this order. projectM
searches its configured texture paths and additionally accepts `jpeg`. File names are matched without regard to letter
case in projectM.

Every `sampler_<name>` declared in a shader causes the image to be loaded, even if the sampler is never used. If a
texture cannot be found, the preset still loads, but the effect using it will not look as intended. projectM binds a
small placeholder texture in this case. Presets intended for distribution should only use textures that ship with the
preset or with the common texture packs.

## Texture Size

For every texture, the shader can declare a `float4` variable named `texsize_<name>`, which contains the image size:

| Component | Value      |
|-----------|------------|
| `x`       | Width      |
| `y`       | Height     |
| `z`       | 1 / width  |
| `w`       | 1 / height |

This is useful to keep an image's aspect ratio, or to sample neighboring texels:

```hlsl
sampler sampler_clouds;
float4 texsize_clouds;

shader_body {
    float2 tile = uv * texsize.xy * texsize_clouds.zw;  // one image texel per screen pixel
    ret = tex2D(sampler_clouds, tile).xyz;
}
```

## Random Textures

Instead of a fixed file name, a preset can ask for a randomly selected image, so that the preset looks different each
time it is loaded. Random textures use the special names `rand00` to `rand15`:

```hlsl
sampler sampler_rand00;               // any image from the textures directory
sampler sampler_rand01_smalltiled;    // an image whose name starts with "smalltiled"
```

- The two digits select one of 16 slots. Use each slot only once per shader.
- An optional `_<prefix>` limits the choice to files whose names start with the prefix. Letter case is ignored.
- Only images in the `textures` directory are candidates, not images in the preset's directory.
- The choice is made when the shader is compiled, i.e. when the preset is loaded.
- `texsize_rand00` etc. contain the size of the image that was chosen for the slot.
- Filtering prefixes can be combined with random names, e.g. `sampler_pc_rand00_smalltiled`.

If no matching image exists, no texture can be bound and the effect will not render as intended. Use prefixes that match
the textures commonly distributed with Milkdrop.

::note
In Milkdrop, each shader chooses its random textures independently. If both the warp and the composite shader declare
`sampler_rand00`, they can receive two different images. If a preset needs the same image in both shaders, use a fixed
texture name instead.
::

## Compatibility Notes

- projectM selects random textures using the system's random number generator. The selection cannot be reproduced and is
  not affected by the `rand()` expression function.
- Milkdrop loads images through Direct3D, while projectM uses its own image loader. Images with an alpha channel may
  therefore produce slightly different colors where they are transparent.
